# रिसर्च-ओएस

`रिसर्च-ओएस` किसी उत्पन्न दस्तावेज़ से अनुसंधान को एक स्थिर प्रमाण पैकेज में बदल देता है। यह मूल स्रोत की सत्यता को सुरक्षित रखता है, दावों को संश्लेषण से अलग करता है, विभिन्न चरणों के माध्यम से तैयारी सुनिश्चित करता है, समीक्षक और छूट संबंधी निर्णयों को रिकॉर्ड करता है, और एक ऐसा पैकेज प्रकाशित करता है जिसके दावों का पता लगाया जा सकता है और उनकी पुष्टि की जा सकती है।

यह आपसे मॉडल पर भरोसा करने के लिए नहीं कहता है। यह आपको यह तय करने के लिए आवश्यक उपकरण प्रदान करता है कि क्या मॉडल, स्रोत और संश्लेषण ने विश्वास अर्जित किया है।

## यह क्या है

`रिसर्च-ओएस` "मैं एक्स पर शोध करना चाहता हूं" और एक स्थिर, दावा-आधारित प्रमाण आधार के बीच नियंत्रण तल है। यह खोज निष्कर्षों को प्राप्त किए गए साक्ष्यों से अलग करता है, कच्चे निष्कर्षण को वर्गीकृत दावों से अलग करता है, विरोधाभास का पता लगाने को विरोधाभास समाधान से अलग करता है, और समीक्षा निर्णयों को संश्लेषण परिणामों से अलग करता है। प्रत्येक चरण केवल एक बार लिखने योग्य लेज़र में दर्ज होता है; प्रत्येक तैयारी निर्णय उन लेज़रों से गणना की जाती है, न कि अनुमानित।

यह कोई रिपोर्ट जनरेटर नहीं है। यह कोई एलएलएम-ऑर्केस्ट्रेशन ढांचा नहीं है। यह आपके संश्लेषण को स्वयं नहीं लिखता है। यह उन शर्तों को लागू करता है जिनके तहत संश्लेषण शुरू किया जा सकता है।

स्थिर पैकेज [`mcp-tool-shop-org/research-packs`](https://github.com/mcp-tool-shop-org/research-packs) में संग्रहीत हैं - छह बंद डॉगफूड प्रयोगों को कवर करते हुए चार पैकेजों के साथ, यह लाइव है। v1.0 पथ के लिए [`docs/roadmap.md`](docs/roadmap.md) देखें।

v0.1 का परीक्षण दो डॉगफूड चक्रों में किया गया है। पहले - रिसर्च-ओएस अपने स्वयं के विनिर्देश पर शोध कर रहा है - ने v0.1.0 रिलीज़ से पहले सात सटीकता संबंधी कमियों को पाया, जिनमें से प्रत्येक को वास्तविक कोड सुधार की आवश्यकता थी और एक नियम या एकीकरण पैटर्न अर्जित करना पड़ा। दूसरे (v1 प्रयोग 1: ComfyUI वर्कफ़्लो स्थायित्व, 11 सत्र, एक ऐसा डोमेन जिसमें रिसर्च-ओएस के साथ कोई शब्दावली ओवरलैप नहीं है) ने 2026-05-09 को बंद कर दिया: पैकेज स्थिर, संग्रह लाइव, पैटर्न 2 प्रवर्तन कमिट `22b5dba` के माध्यम से पूरा किया गया। v0.1 प्रमाण पथ [`docs/dogfood-proof.md`](docs/dogfood-proof.md) में है; प्रयोग 1 का प्रमाण [`docs/experiment-1-proof.md`](docs/experiment-1-proof.md) में है। लाइव हैंडबुक: <https://mcp-tool-shop-org.github.io/research-os/handbook/>।

## स्थापित करें

**आवश्यकताएं:** Node.js ≥ 20।

```bash
npm install -g @mcptoolshop/research-os
```

स्रोत से निर्माण करने वाले योगदानकर्ताओं के लिए:

```bash
git clone https://github.com/mcp-tool-shop-org/research-os.git
cd research-os
npm install
npm run build
npm link
```

## त्वरित शुरुआत

```bash
# Create a new research-pack
research-os init "How should X be structured?"

# Add a section
research-os section add 01-landscape --purpose "Map the current landscape"

# Discover and approve sources, then gather
research-os discover run 01-landscape
research-os discover approve 01-landscape --top 8
research-os gather 01-landscape --approved

# Run the per-section chain
research-os claim extract 01-landscape
research-os claim audit-density 01-landscape
research-os claim triage 01-landscape
research-os contradict map 01-landscape --triaged-only
research-os review 01-landscape --triaged-only --preset hermes-two-pass --profile hermes-two-pass
research-os review-promote 01-landscape --profile hermes-two-pass
research-os gate 01-landscape
research-os section report 01-landscape

# Pack-level finish
research-os audit
research-os index build --all
research-os cowork handoff
research-os synth workspace   # only if handoff returned synthesis_ready
research-os freeze

# Export to the research-packs archive
research-os pack publish \
  --to <research-packs>/packages/<name>
```

> **`freeze` आउटपुट पर ध्यान दें।** `रिसर्च-ओएस freeze` चुपचाप काम करता है क्योंकि यह प्रत्येक मानक कलाकृति को स्कैन करता है और सामग्री हैश की गणना करता है - इस कमांड के लिए कोई वृद्धिशील प्रगति नहीं होती है। बड़े पैकेजों पर, कुछ भी प्रिंट करने से पहले इसमें दसियों सेकंड लग सकते हैं। जब यह समाप्त हो जाता है तो यह एक एकल निर्णय ब्लॉक (`PASS` / `REFUSED` प्लस रसीद पथ) प्रिंट करता है। अंतराल को किसी रुकावट के रूप में न समझें।

> **`--force` चेतावनी।** `--force` लक्ष्य पैकेज निर्देशिका को साफ़ और बदल देता है। उत्पन्न पैकेज आउटपुट के अंदर हाथ से लिखी गई फ़ाइलों को न रखें। इसके बजाय, अपस्ट्रीम कलाकृतियों (दावे, स्रोत, संश्लेषण) या संबंधित फ़ाइलों को संपादित करें। पूर्ण स्वीकृति अनुबंध + अस्वीकृति मामले: [`docs/pack-publish.md`](docs/pack-publish.md)।

**वास्तविक उदाहरण के लिए**, `research-os-packs/research-os-spec/` में डॉगफूड पैकेज देखें - प्रत्येक कलाकृति, प्रत्येक रसीद, प्रत्येक परिणाम, प्रत्येक फ्रीज फ़िंगरप्रिंट, सब कुछ केवल एक बार लिखने योग्य लेज़रों में डिस्क पर है। वह पैकेज वही है जिससे `docs/dogfood-proof.md` उत्पन्न हुआ था।

**एलएलएम निष्कर्षण, वर्गीकरण, समीक्षा और खोज के लिए स्थानीय रूप से चल रहे [`ollama-intern-mcp@^2.4.0`](https://github.com/mcp-tool-shop-org/ollama-intern-mcp) की आवश्यकता है।** एमसीपी सर्वर को `OLLAMA_INTERN_MCP_BIN` पर्यावरण चर या PATH के माध्यम से खोजा जाता है। डिफ़ॉल्ट मॉडल `hermes3:8b` है; इसे `OLLAMA_INTERN_MODEL=<model>` (या प्रति-कॉल `--model <name>`) से बदलें। यदि ओलामा डिफ़ॉल्ट `localhost:11434` पर नहीं है, तो `OLLAMA_HOST` सेट करें।

| # | नियम |
|---|-----|
| 1 | स्रोत सत्य से पहले कोई संश्लेषण नहीं। |
| 2 | प्राप्ति प्रमाण है; निष्कर्षण व्याख्या है। |
| 3 | मॉडल स्रोत स्पैन की व्याख्या कर सकते हैं; वे साक्ष्य स्पैन को अधिकृत नहीं कर सकते। |

| 5 | विरोधाभास मानचित्रण तनाव को उजागर करता है; यह समाधान, संश्लेषित या निर्णय नहीं लेता कि कौन सा दावा जीतता है। |
| 6 | गेट तय करते हैं कि क्या कोई अनुभाग संश्लेषण के लिए योग्य है। वे संश्लेषित या विफलता को छिपाते नहीं हैं। |
| 7 | विरोधी समीक्षा अनुसंधान अखंडता का मूल्यांकन करती है। यह संश्लेषित या स्रोत सत्य को फिर से नहीं लिखता है। |
| 8 | अनुक्रमण अनुसंधान सत्य को क्वेरी करने योग्य बनाता है। यह नया सत्य नहीं बनाता है और न ही यह रिकॉर्ड का स्रोत बन जाता है। |
| 9 | सहकर्मी हैंडऑफ़ अनुसंधान सत्य से परिचालन निर्देश प्रस्तुत करता है। यह सत्य नहीं बनाता है और न ही गेटों को बायपास करता है। |
| 10 | संश्लेषण कार्यक्षेत्र सहकर्मी के लिए स्वीकृत अनुसंधान सत्य को व्यवस्थित करता है। यह संश्लेषण नहीं बनाता है और न ही हैंडऑफ़ मोड को बायपास करता है। |
| 11 | पैकेज ऑडिट मौजूदा अनुसंधान सत्य को एकत्रित करता है। यह नया सत्य नहीं बनाता है और न ही अनुभाग-स्तरीय साक्ष्य को छिपाता है। |
| 12 | खोज प्रस्तावों का प्रस्ताव करती है; केवल प्राप्ति प्रमाण उत्पन्न करती है। |
| 13 | समीक्षक पर तब तक भरोसा नहीं किया जाता जब तक कि बीजित विफलताओं से स्मरण सिद्ध न हो जाए। |
| 14 | दावों की प्रचुरता अनुसंधान गुणवत्ता नहीं है। संश्लेषण के लिए प्रतिस्पर्धा करने से पहले दावों को वर्गीकृत किया जाना चाहिए। |
| 15 | फ्रीज पूर्ण अनुसंधान सत्य को लॉक करता है। यह अधूरे अनुसंधान को पूरा नहीं करता है और न ही मरम्मत स्थिति को साक्ष्य में परिवर्तित करता है। |
| 16 | छूट स्रोत बाधाओं को कम करती हैं; वे साक्ष्य का निर्माण नहीं कर सकते। |

**नियम 3** - एलएलएम कभी भी साक्ष्य पाठ को अधिकृत नहीं करता है। रिसर्च-ओएस एक नियतात्मक अंश लेज़र बनाता है (स्थिर आईडी जैसे `ex_<source_id_hex>_001`); एलएलएम अंश आईडी चुनता है; रिसर्च-ओएस शाब्दिक पाठ की प्रतिलिपि बनाता है। "उद्धरण के रूप में पैराफ़्रेज़" विफलता वर्ग संरचनात्मक रूप से असंभव है।

**नियम 14** - निष्कर्षण और समीक्षा के बीच, `research-os claim triage` डुप्लिकेट को हटाता है, प्रति-स्रोत योगदान को सीमित करता है, और कम प्रभाव वाले उम्मीदवारों को अलग रखता है। ट्राइएज `claims.jsonl` में बदलाव नहीं करता; अलग रखे गए दावे आधिकारिक रिकॉर्ड में बने रहते हैं।

## v0.1 वर्कफ़्लो श्रृंखला

```
discover
→ gather
→ claim extract
→ claim audit-density
→ claim triage
→ contradict map
→ contradict resolve
→ review
→ review-promote
→ gate
→ section report
→ audit
→ index build
→ cowork handoff
→ synth workspace
→ freeze
```

प्रत्येक चरण एक CLI कमांड है। प्रत्येक चरण केवल-जोड़ने योग्य कलाकृतियों में लिखता है। कोई भी चरण संश्लेषण, समाधान या नया सत्य नहीं बनाता - इन अपरिवर्तनीय नियमों को लागू किया जाता है, उन पर भरोसा नहीं किया जाता। समीक्षा उम्मीदवार दावों पर स्वीकृति/अस्वीकृति/मरम्मत का अनुरोध करती है; गेट उन समीक्षा निर्णयों का उपयोग `synthesis_eligible` की गणना करने के लिए करता है; फ़्रीज़ अंतिम अखंडता लॉक है जो तब तक किसी पैक को पूरा हुआ चिह्नित करने से इनकार करता है जब तक कि हर परत सहमत न हो जाए। v0.1 प्रमाण के लिए [docs/dogfood-proof.md](docs/dogfood-proof.md) देखें, जो दर्शाता है कि श्रृंखला अंत-से-अंत तक कैसे काम करती है।

यह *खोज → सारांशित करें → सुंदर रिपोर्ट* का संरचनात्मक विकल्प है। श्रृंखला ही उत्पाद है।

## सुरक्षा

`research-os` एक स्थानीय-प्रथम CLI है। यह उस शोध-पैक निर्देशिका के भीतर फ़ाइलों को पढ़ता और लिखता है जिसे आप इंगित करते हैं, और (जब `gather` का उपयोग किया जाता है) आपके द्वारा प्रदान किए गए स्रोत URL प्राप्त करने के लिए आउटबाउंड HTTP अनुरोध जारी करता है। यह नहीं करता: सर्वर चलाता है, इनबाउंड कनेक्शन स्वीकार करता है, क्रेडेंशियल्स संग्रहीत करता है, या टेलीमेट्री भेजता है। कोई भी गुप्त जानकारी पैक कलाकृतियों में नहीं लिखी जाती है। भेद्यता रिपोर्टिंग नीति के लिए [SECURITY.md](SECURITY.md) देखें।

## समीक्षक अंशांकन

v0.5.0 समीक्षक अंशांकन को स्थायी बनाता है। एक समीक्षक प्रोफ़ाइल पर भरोसा नहीं किया जाता क्योंकि यह केवल एक बार चला था; यह संरचित सीडेड-विफलता रसीदों और बहु-रन एकत्रीकरण के माध्यम से स्थिति अर्जित करता है। v0.6.0 उत्पादन समीक्षा पथ और अंशांकन हार्नेस में नियतात्मक समीक्षक विकल्प जोड़ता है।

**वर्तमान में कोई भी प्रोफ़ाइल `trusted_baseline` के रूप में स्वीकार नहीं की जाती है।** रिपॉजिटरी में मौजूद आधिकारिक रसीदें `hermes-two-pass=failed`, `mistral-nemo-two-pass=conditional_pass`, `hermes-single-pass=comparison_only`, `hermes-two-pass-deterministic=failed` दिखाती हैं। यह जानबूझकर किया गया है: बार-बार सीडेड-विफलता के प्रमाण के माध्यम से विश्वास अर्जित किया जाता है, न कि मान लिया जाता है। `hermes-two-pass-deterministic` रसीद में एक संरचनात्मक मॉडल-क्षमता अंतर है (2/6 निर्णय प्रकार उत्पन्न; 3/6 की आवश्यकता है) जो कोई विचलन समस्या नहीं है।

अंशांकन रसीदें `calibration/reviewer-profiles/<profile>/seeded-v1.{json,md}` पर स्थित हैं। प्रत्येक रसीद सात बारों के विरुद्ध PASS/FAIL रिकॉर्ड करती है, चार स्थिति लेबल (`trusted_baseline`, `conditional_pass`, `failed`, `comparison_only`), और ईमानदारी से खुलासा करती है कि फिक्स्चर क्या परीक्षण नहीं कर सकता (`needs_contradiction_mapping` `seeded-v1` से अप्राप्य है)। [CHANGELOG.md](CHANGELOG.md) देखें।

```bash
# Single-run calibration (quick local check)
node scripts/reviewer-calibration.mjs --model hermes3:8b --two-pass --profile hermes-two-pass

# Multi-run aggregate calibration (canonical evidence — 3 runs, median-based PASS/FAIL)
node scripts/reviewer-calibration.mjs --model hermes3:8b --two-pass --profile hermes-two-pass --runs 3

# Deterministic multi-run calibration (temperature + seed explicit in receipt)
node scripts/reviewer-calibration.mjs --model hermes3:8b --two-pass \
  --temperature 0 --seed 7 --runs 3 --profile hermes-two-pass-deterministic

# Promote a section's review — auto-populates calibration_summary from pack-relative receipt
research-os review-promote 01-section --pack <pack> --profile hermes-two-pass
```

जब `--runs <n>` का उपयोग किया जाता है, तो प्रति-रन रसीदें `<profile>/runs/run-NNN.json` पर लिखी जाती हैं और एक एकत्रित रसीद (मध्यक-आधारित बारों और आवर्ती-विफलता पहचान के साथ) `<profile>/seeded-v1.{json,md}` पर लिखी जाती है। एकत्रित रसीद `receipt_kind: 'aggregate'` ले जाती है ताकि इसे एकल-रन रसीदों से अलग किया जा सके। एकल-रन मोड (`--runs 1` या छोड़ा गया) मौजूदा प्रत्यक्ष-लेखन व्यवहार को बनाए रखता है।

**नियतात्मक समीक्षक प्रोफ़ाइल** - `research.yaml` में `review_profiles.<name>.reviewer_options` का उपयोग करें ताकि `temperature`, `seed` और अन्य ओलामा सैंपलिंग पैरामीटर को उत्पादन समीक्षा पथ में प्रत्येक `OllamaInternReviewer` निर्माण में शामिल किया जा सके। `hermes-two-pass-deterministic` प्रोफ़ाइल एक अंतर्निहित उदाहरण के रूप में शिप की जाती है। [`docs/experiment-6-proof.md`](docs/experiment-6-proof.md) और [समीक्षक अंशांकन हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/research-os/handbook/reviewer-calibration/) देखें।

## v0.13.1 में नया - R-024 एक्सट्रैक्ट-स्टेज टियर-बजट अथॉरिटी (पथ C पैच)

v0.13.1 v0.13.0 के शीर्ष पर एक एकल-मरम्मत पैच है। यह v0.5 ट्रैक-सी स्थिति (R-019 वायर-अप स्कोप अंतर दावों को निकालने के चरण में) को R-019 के टियर-बजट अधिकार को हर `ollama_extract` MCP कॉल तक विस्तारित करके बंद कर देता है जो `claim extract` के दौरान किया जाता है - प्रति-विंडो एक्सट्रैक्टर, प्रति-दावा R-011 अनुभाग-सबूत आलोचक, और प्रति-बचाव-उम्मीदवार R-012 बचाव आलोचक। यह R-019 के सिंथ-प्रोसे कवरेज के समान वास्तुशिल्प आकार है। एकल-रिपॉजिटरी पैच (केवल research-os); ollama-intern-mcp@2.6.0 का `tier_budget_ms_override` स्कीमा फ़ील्ड अपरिवर्तित सर्वर-साइड पहुंच है।

यह रिलीज़ इसलिए मौजूद है क्योंकि प्रकाशित `@mcptoolshop/research-os@0.13.0` + `ollama-intern-mcp@2.6.0` के विरुद्ध v0.5 ऑपरेटर-अकेलापन गेट ने **PASS_WITH_CONDITIONS, NOT प्राधिकरण-ग्रेड** (`operator_aloneness_dst_v0.5`) लौटाया। सभी v0.13 सतहें (R-018 + R-019 + R-020 + R-021) बिना किसी बग के लाइव रूप से काम करती हैं; रक्षा तल संरक्षित है; प्रलेखित `recovery_actions` के साथ नामित विफलताओं पर ईमानदार इनकार। लेकिन अनुभाग 02 (`02-safety-and-economic`) में 8 स्रोतों में से 3 ने एक्सट्रैक्ट के दौरान आंतरिक 15000ms इंस्टेंट-टियर TIER_TIMEOUT को हिट किया, जिसमें ऑपरेटर-फेसिंग ओवरराइड नहीं था। R-019 ने v0.13.0 में सिंथ प्रोस के लिए एनालॉग ओवरराइड भेजा था; v0.13.1 इसे एक्सट्रैक्ट चरण तक विस्तारित करता है।

> **R-024 पूर्ण-कवरेज टियर-बजट नियम लागू करता है: जब किसी टियर बजट का विस्तार किया जाता है, तो बजट को उस चरण में हर LLM कॉल तक पहुंचना चाहिए जो समान आंतरिक टाइमआउट उत्पन्न कर सकता है। आंशिक कवरेज = कॉल-साइट-कवरेज परत पर गलत लक्ष्य वाला पैच।**
> **R-024 लाइव-रिप्ले परीक्षण भंगुरता नियम भी लागू करता है: जब एक लाइव-रिप्ले स्वीकृति परीक्षण हार्नेस कारणों (समय, कैप्चर, फिक्स्चर स्थिति) के बजाय तंत्र कारणों से विफल हो जाता है, तो परीक्षण हार्नेस को ठीक करें - मैन्युअल कलाकृति निरीक्षण को छोड़ें, कम न करें या प्रतिस्थापित न करें।**

v0.5 संस्करण का कार्यान्वयन पाथ डी (मल्टी-ट्रैक ट्राइएज) है। v0.13.1 ट्रैक सी को बंद करता है। ट्रैक ए, स्केफोल्डिंग (मेमोरी-गेट हुक पाथ व्हाइटलिस्ट) में बंद किया गया। ट्रैक बी (स्रोत-खोज स्केफोल्डिंग) v0.13.1 के प्रकाशित होने के बाद एक अलग सत्र में शुरू होता है। v0.6 गेट सेटअप, ट्रैक बी का अनुसरण करता है। स्वीकार्यता स्लाइस 1, v0.6 पास होने तक **अधिकृत नहीं** रहेगा।

### आप क्या चला सकते हैं

```sh
#         (mirrors R-019's --planner-timeout-ms for synth prose; same shape, different stage)
```

प्राथमिकता: CLI ध्वज > पर्यावरण चर > डिफ़ॉल्ट (छोड़ा गया; ओल्लामा-इंटरन-एमसीपी प्रोफ़ाइल डिफ़ॉल्ट लागू)। सीमित `[1, 600000]` एमएस (10 मिनट की ऊपरी सुरक्षा सीमा)। अमान्य मान स्पष्ट रूप से गैर-शून्य एग्जिट कोड के साथ विफल हो जाते हैं, जो सतह + उल्लंघन करने वाले मान को इंगित करते हैं।

### नया क्या है

**आर-024 - सभी 3 `ओल्लामा_एक्सट्रैक्ट` कॉल साइटों में एक्सट्रेक्ट-स्टेज टियर-बजट प्राधिकरण।** `क्लेम एक्सट्रेक्ट` (और मिलान करने वाले `रिसर्च_ओएस_एक्सट्रैक्ट_टीयर_बजट_एमएस` पर्यावरण चर) पर नया `--टीयर-बजट-एमएस <एन>` ध्वज, ऑपरेटर द्वारा नियंत्रित प्रति-कॉल टियर-बजट ओवरराइड को `ओल्लामा-इंटरन-एमसीपी@>=2.6.0` में `टीयर_बजट_एमएस_ओवरराइड` के रूप में प्रत्येक `ओल्लामा_एक्सट्रैक्ट` कॉलटूल आह्वान के दौरान एक्सट्रेक्ट रन के दौरान भेजता है: `एमसीपीक्लेमएक्स्ट्रैक्टर.एक्सट्रैक्टवनपेज` (प्रति-विंडो एक्सट्रैक्टर), `रनक्रिटिक` (आर-011 प्रति-दावा अनुभाग-सबूत आलोचक, प्रति ड्राफ्ट प्रति विंडो एक कॉल), और `रनरेस्क्यूक्रिटिक` (आर-012 प्रति-बचाव-उम्मीदवार बचाव आलोचक स्रोत_सामग्री_असंगति ड्राफ्ट पर)। सक्रिय बजट stderr में दिखाई देता है (`[एक्सट्रैक्ट] टीयर_बजट_एमएस=एन सोर्स=... सेक्शन=<आईडी>`), एक्सट्रेक्ट रसीद मेटाडेटा में (`टीयर_बजट_एमएस` + `टीयर_बजट_ओवरराइडन_बाय`) `ऑडिट्स/<सेक्शन>-क्लेम-एक्सट्रैक्ट.json`), और बंद एनम `एक्सट्रैक्ट_टीयर_बजट_सोर्सेस` (`['डिफ़ॉल्ट', 'cli_flag', 'env_var']`) में। डिफ़ॉल्ट व्यवहार v0.13.0 के समान है (कोई ध्वज नहीं, कोई पर्यावरण चर नहीं → प्रोफ़ाइल डिफ़ॉल्ट लागू; रसीद नए फ़ील्ड को छोड़ देती है)।

### आर्किटेक्चरल नोट

आर-024 आर-019 के आर्किटेक्चर को दर्पण करता है, लेकिन एक अलग चरण पर। आर-019 ने ओवरराइड को `रनप्रोसेसिंथेसिस` के माध्यम से प्लानर + ड्राफ्टर + वेरिफायर (3 सिंथ-प्रोसे `ओल्लामा_एक्सट्रैक्ट` कॉल साइट) तक पहुंचाया; आर-024 इसे `एक्सट्रैक्ट()` ऑर्केस्ट्रेटर → `एमसीपीक्लेमएक्स्ट्रैक्टर.एक्सट्रैक्ट` → एक्सट्रेक्टवनपेज + रनक्रिटिक + रनरेस्क्यूक्रिटिक (3 एक्सट्रेक्ट-स्टेज `ओल्लामा_एक्सट्रैक्ट` कॉल साइट) तक पहुंचाता है। पूर्ण-कवरेज टियर-बजट नियम अब एक महत्वपूर्ण सिद्धांत है: ऑपरेटर-फेसिंग सतह के लिए टियर बजट का विस्तार करते समय, चरण बी रिपोर्ट-बैक को उस चरण में प्रत्येक एलएलएम कॉल साइट को सूचीबद्ध करना चाहिए जो समान आंतरिक टाइमआउट साझा करता है। आंशिक कवरेज कॉल-साइट-कवरेज परत पर आर-018 के रैपर/आंतरिक-तंत्र एमआईएसटार्गेटेड-पैच के समान स्व-झूठ बोलने वाले हस्ताक्षर के साथ एक एमआईएसटार्गेटेड-पैच उत्पन्न करता है: रसीद ओवरराइड को रिकॉर्ड करती है और नामित टाइमआउट उसी कलाकृति में एक अप्रकाशित कॉल साइट पर शुरू होता है।

शून्य ओल्लामा-इंटरन-एमसीपी परिवर्तन। v2.6.0 के `टीयर_बजट_एमएस_ओवरराइड` स्कीमा फ़ील्ड को आर-019 के समन्वित रिलीज़ से लागू किया गया था; v0.13.1 अनुसंधान-ओएस-साइड एक्सट्रैक्ट-स्टेज क्लाइंट वायर-अप प्रदान करता है।

### नया क्या है

**आर-019 - आंतरिक एमसीपी टियर-बजट क्लाइंट वायर-अप।** आर-018 का `--planner-timeout-ms <N>` फ्लैग (और `RESEARCH_OS_SYNTH_PLANNER_TIMEOUT_MS` एनवायरनमेंट वेरिएबल) अब प्लानर/ड्राफ्टर/वेरीफायर के माध्यम से `ollama_extract.tier_budget_ms_override` में जाता है, और `ollama-intern-mcp/src/guardrails/timeouts.ts:61` पर `runWithTimeoutAndFallback` तक पहुंचता है। आंतरिक प्रति-टियर टाइमआउट तंत्र जो v0.4 रीरन के `elapsed=15018ms budget=15000ms` विफलता का कारण बना, अब सीधे ऑपरेटर के बजट का पालन करता है। आर-018 रैपर को बाहरी हार्ड-रेल के रूप में बरकरार रखा गया है ताकि अनसुलझे प्रॉमिस हैंग्स से बचा जा सके (ऑर्थोगोनल विफलता मोड रैपर्स वास्तव में इसे पकड़ सकते हैं)। इसके लिए `ollama-intern-mcp@>=2.6.0` की आवश्यकता होती है; पुराने संस्करण चुपचाप नए स्कीमा फ़ील्ड को अनदेखा करते हैं (आर-018 रैपर अभी भी अपनी मूल परत पर काम करता है - अनुग्रहपूर्ण गिरावट)।

**आर-020 (केवल डी) - `no_answer_cluster` रिकवरी सतह।** जब प्लानर किसी स्वीकृत दावे को `role=answer` असाइन करने से इनकार कर देता है, तो विफलता अब इनलाइन `recovery_actions[]` (`narrow_section_purpose` + `add_on_topic_sources`) को `section-synthesis.json` में प्रदर्शित करती है, जो कि `section-synthesis.md` में रेंडर किए गए `## Recovery actions` मार्कडाउन ब्लॉक (एक्शन_आईडी हेडिंग + क्यों टेक्स्ट + फेन्स्ड कमांड_हिंट कोड ब्लॉक) और एक सिंगल-लाइन stderr हिंट (`[synth] no_answer_cluster — see section-synthesis.md "Recovery actions" block for actionable steps`) के रूप में होता है। एक्शन सूची कार्रवाई-ग्राफ रिकवरी पथ के साथ साझा की जाने वाली सच्चाई का एकमात्र स्रोत है; स्टैंडअलोन-कमांड और इनलाइन-विफलता-बॉडी पथों के बीच कोई विचलन नहीं। **आर-020 के प्लानर प्रॉम्प्ट ट्यून (ए-हाफ) को आज़माया गया और वापस ले लिया गया** - iter-1 ने चुपचाप गलत संश्लेषण उत्पन्न किया (एलएलएम ने प्रतिकूल फिक्स्चर पर सकारात्मक-प्रभाव दावों से शून्य-प्रभाव उत्तर बनाए; वेरीफायर ने उलटे निषेध को `faithful` के रूप में स्वीकार किया); iter-2 के हार्ड गार्डरेल ने मतिभ्रम को ओवरराइड नहीं किया। ऑपरेटर के एक-पुनरावृत्ति नियम के अनुसार, प्रॉम्प्ट और 3 v3-पिन्ड परीक्षण फ़ाइलों को वापस ले लिया गया; `PROSE_PROMPT_VERSION` `section-prose-v3` पर बना हुआ है। सिद्धांत रैटचेट अर्जित: संरचनात्मक लाइव रीप्ले तब तक पास हो सकता है जब तक कि संश्लेषित सामग्री चुपचाप गलत न हो; प्रतिकूल फिक्स्चर पर निषेध/दायरा/पूर्वानुमान व्युत्क्रम को पकड़ने के लिए मैनुअल गद्य निरीक्षण की आवश्यकता होती है।

**आर-021 - कंट्राडिक्ट-मैप ऑटो-मोड हैंग-टाइमआउट + हेयुरिस्टिक फॉल-थ्रू + दृश्यमान प्रगति।** नया `--auto-mode-pair-timeout-ms <N>` (डिफ़ॉल्ट 90000; आर-021 से पहले हार्डकोडेड 120 सेकंड से कम किया गया, गेट-मापा हुआ वार्म हर्मेस3:8b v0.4 फिक्स्चर पर: न्यूनतम 6.2 सेकंड, माध्यिका 8.4 सेकंड, अधिकतम 8.8 सेकंड → 90 सेकंड डिफ़ॉल्ट में ≥81 सेकंड का हेडरूम है)। नया `--auto-mode-fall-through-after-n-timeouts <N>` (डिफ़ॉल्ट 5; स्वचालित हेयुरिस्टिक फॉल-थ्रू के लिए लगातार-विफलता सीमा; सफल `type:none` वर्गीकरण काउंटर को रीसेट करते हैं)। मिलान करने वाले एनवायरनमेंट वेरिएबल। प्रत्येक आह्वान पर उत्सर्जित नया stdout स्टार्ट लाइन (`auto-mode engaged: N candidate pairs; per-pair timeout=Xms; fall-through-after=Y`) - हमेशा दृश्यमान, गैर-TTY संदर्भों में भी बना रहता है। मजबूर-उत्सर्जित stderr फॉल-थ्रू ट्रिगर इवेंट TTY-गेटिंग / `--progress` को बायपास करता है क्योंकि ऑपरेटर को मोड-स्विच देखना चाहिए। जब सीमा पार हो जाती है तो `contradictions.md` में नया `## Auto-mode fall-through` मार्कडाउन ब्लॉक। केवल अप्रसंस्कृत जोड़े पर हेयुरिस्टिक री-रन (एलएलएम द्वारा पहले से ही पूर्ण किए गए जोड़ों का कोई डुप्लिकेट पुन: वर्गीकरण नहीं)।

v0.12.1, v0.12.0 पर आधारित एक एकल-मरम्मत पैच था। इसने केवल R-018 जारी किया - सिंथ प्रॉज़ एमसीपी `callTool` कॉल पर रिसर्च-ओएस-साइड रैपर टाइमआउट, जिसे एक ऑपरेटर द्वारा खोजे जा सकने वाले CLI ध्वज (`synth section` और `synth workspace` पर `--planner-timeout-ms <N>`) और मिलान करने वाले एनवी चर (`RESEARCH_OS_SYNTH_PLANNER_TIMEOUT_MS=<N>`) के माध्यम से नियंत्रित किया जाता है। प्राथमिकता: CLI ध्वज > एनवी चर > डिफ़ॉल्ट (15000ms)। डिफ़ॉल्ट व्यवहार v0.12.0 के समान ही बनाए रखा गया है।

यह रिलीज़ इसलिए मौजूद है क्योंकि v0.4 ऑपरेटर-अकेलापन गेट `@mcptoolshop/research-os@0.12.0` के विरुद्ध **PASS_WITH_CONDITIONS** लौटा, न कि प्राधिकरण-स्तर का (`operator_aloneness_dst_v0.4`)। v0.11 रक्षा स्तर लाइव लोड के तहत बना रहा; सभी छह v0.12 कवरेज-पुनर्प्राप्ति सतहें सक्रिय हुईं और ऑपरेटर को आगे बढ़ाया; सीलबंद लिफाफे वाले कवरेज ने PASS थ्रेशोल्ड तक पहुंच प्राप्त की (4/5 समर्थित + 1 अनिवार्य आंशिक; 2/3 समर्थित + 1 आंशिक मॉडरेटर; 0/3 जाल; 0/5 सामग्री विफलताएं ट्रिगर हुईं); संदूषण मार्कर सभी हानिरहित थे। एकल विफलता मोड अंतिमकरण था: सिंथ प्रॉज़ ने लगभग 15010ms पर बार-बार `TIER_TIMEOUT` हिट किया, जबकि 15 सेकंड के तत्काल-स्तर बजट में कोई प्रलेखित ऑपरेटर ओवरराइड नहीं था। अनुभाग संक्षिप्त विवरण लिफाफे के अनुरूप थे; पैक बस जमने तक नहीं पहुंच सका।

**पथ C निपटान** (v0.4 पर अर्जित नया पैटर्न): जब सत्र B एक स्पष्ट पैच पथ और लिफाफे वाले कवरेज के PASS थ्रेशोल्ड पर होने, रक्षा स्तर बनाए रखने और संदूषण हानिरहित होने की स्थिति में एकल नामित विफलता तंत्र की पहचान करता है, तो निपटान इस प्रकार होता है - पैच जारी करें, पैच किए गए संस्करण के विरुद्ध समान ऑपरेटर पथ को फिर से चलाएं, पुन: ग्रेडिंग करें। कोई लिफाफे का पुन: प्राधिकरण नहीं। कोई मानव मूल्यांककर्ता नहीं। कोई v0.13 आर्किटेक्चरल आर्क नहीं।

> **v0.4 अनुभाग-संक्षिप्त स्तर पर कवरेज-स्तर के रिसर्च-ओएस को साबित करता है।**
> **v0.12.1 को रक्षा स्तर को कमजोर किए बिना, एकल योजनाकार-टाइमआउट बाधा को दूर करके अंतिमकरण-स्तर को साबित करना होगा।**

### आप क्या चला सकते हैं


सक्रिय बजट सतहें `section-synthesis.json` (`planner_timeout_ms` हमेशा पॉप्युलेटेड + `planner_timeout_overridden_by` केवल ओवरराइड पर मौजूद), प्रॉज़ब्लॉक मेटाडेटा और stderr (`[synth] planner_timeout_ms=N source=… section=<id>`) में पाई जाती हैं, जो प्रॉज़ पीढ़ी से पहले उत्सर्जित होती हैं। `synth section --help` ध्वज, डिफ़ॉल्ट, ऊपरी सीमा (600000ms सुरक्षा रेल) और एनवी-चर विकल्प का दस्तावेजीकरण करता है। अमान्य मान (नकारात्मक, शून्य, गैर-संख्यात्मक, इकाई-सफिक्स स्ट्रिंग, > 600000) स्पष्ट रूप से एक गैर-शून्य निकास कोड के साथ विफल हो जाते हैं जो सतह + उल्लंघन करने वाले मान को नामित करते हैं। कोई मौन फॉलबैक नहीं।

### आर्किटेक्चरल नोट

v0.4 गेट द्वारा हिट किया गया 15000ms बजट `ollama-intern-mcp` (`profiles.ts:58`, `DEV_RTX5080_TIMEOUTS.instant`) में मौजूद है, न कि रिसर्च-ओएस में। R-018 से पहले रिसर्च-ओएस ने किसी भी योजनाकार टाइमआउट को लागू नहीं किया - टाइमआउट ollama-intern-mcp के स्तर नीति में सर्वर-साइड पर ट्रिगर हुआ। R-018 का समाधान एमसीपी `callTool` के चारों ओर एक `Promise.race` रैपर के माध्यम से बजट पर रिसर्च-ओएस के अपने अधिकार का परिचय देता है, जो डिफ़ॉल्ट रूप से वास्तविक देखे गए तत्काल-स्तर संख्या (15000ms) पर होता है ताकि डिफ़ॉल्ट व्यवहार को बनाए रखा जा सके। R-018 का रैपर `TIER_TIMEOUT`-आकार की त्रुटियां उत्पन्न करता है जो R-010 `classifyFallbackCause` रेगुलर एक्सप्रेशन (`/elapsed=(\d+)ms/` + `/budget=(\d+)ms/`) से मेल खाती हैं, जिससे डिफ़ॉल्ट-पथ रनों पर डाउनस्ट्रीम एआई-सलाहकार दृश्यता बनी रहती है।

v0.12.0 16 मई, 2026 को सामने आए v0.3 ऑपरेटर-अकेलापन गेट निष्कर्षों को बंद करता है (`operator_aloneness_dst_v0.3`, PASS_WITH_CONDITIONS लेकिन प्राधिकरण-स्तर नहीं)। चार स्लाइस में छह नामित निष्कर्ष: तीन आर्किटेक्चरल मरम्मत जो v0.4-अवरोधक कवरेज अंतराल को बंद करते हैं (R-012, R-013, R-014), और तीन एर्गोनोमिक समापन जो ऑपरेटर सतह में सुधार करते हैं जिस पर v0.4 गेट अभ्यास करेगा (R-015, R-016, R-017)। v0.3 विफल नहीं हुआ क्योंकि रक्षा कमजोर हो गई - सभी पांच v0.11 रक्षा सतहें ठीक उसी तरह सक्रिय हुईं जैसा कि डिज़ाइन किया गया था, शून्य मौन-गलत सामग्री के साथ एक स्वच्छ ईमानदार संश्लेषण उत्पन्न किया, और पैक वास्तविक लेकिन संकीर्ण साक्ष्य पर जम गया। यह विफल रहा क्योंकि समान रक्षा, सही ढंग से काम करते हुए, स्वीकार किए गए दावे के आधार से भार-असर प्राथमिक-स्रोत कवरेज को हटा दिया। v0.3 पर अर्जित सिद्धांत रैटचेट:

### कानूनी सीमा

पैक-कानून प्रतिबंध बरकरार रखे गए। `accepted_claim_floor` अपरिवर्तनीय रहता है। बंद `FailureShape` एनम में नौ मान हैं, जो अपरिवर्तित हैं। `RECOVERY_ACTIONS` एनम में 8 मान हैं - कोई नया सलाहकार कार्रवाई नहीं; R-014 की विशिष्ट-आकृति ह्यूरिस्टिक मौजूदा कार्रवाइयों के रूटिंग को विस्तृत करती है। AI पुनर्प्राप्ति सलाहकार प्रॉम्प्ट टेम्पलेट अपरिवर्तित है (नए `EvidenceState` फ़ील्ड लगातार JSON में देखे जा सकते हैं, लेकिन प्रॉम्प्ट में प्रदर्शित नहीं किए जाते)। पुनर्प्राप्ति सत्यापन नियम अपरिवर्तित हैं। MCP आर्किटेक्चर अपरिवर्तित है - `ollama-intern-mcp@^2.4.0` का उपयोग किया जाता है; निष्कर्षण पर कोई MCP कॉल आकार परिवर्तन नहीं। R-017 की चेतावनी सूचनात्मक है और गेट निर्णय, फ़्रीज़ रसीद या पैक-प्रकाशित को प्रभावित नहीं करती है। सभी v0.10 + v0.11 सुरक्षा उपाय बरकरार रखे गए हैं; रक्षा प्रणाली अपरिवर्तित है और v0.12 इस पर आधारित है।

- **B-E-004 — npm उत्पत्ति प्रमाणन को भविष्य के रिलीज़ में स्थगित कर दिया गया है।** v0.12.1 npm टारबॉल केवल पैकेज-शासम के माध्यम से सत्यापित होता है। प्रकाशन प्रवाह को sigstore OIDC के साथ CI वर्कफ़्लो में स्थानांतरित करने से प्रकाशन-से-पहले अनुवाद अनुशासन का विरोध होता है (TranslateGemma 12B स्थानीय रूप से चलता है); प्रवासन की योजना भविष्य के रिलीज़ के लिए बनाई गई है। पैकेज-शासम और GitHub रिलीज़ कमिट के माध्यम से v0.12.1 npm पैकेजों को सत्यापित करें।
- **B-A-003 — इंडेक्सर स्कीमा-संस्करण प्रवासन प्रलेखित है, लेकिन लागू नहीं किया गया है।** v0.12.1 एक लेखन-पक्ष `SCHEMA_VERSION` पूर्णांक और कोई भी पढ़ने-पक्ष प्रवासन रनर शामिल करता है। प्रलेखित `SCHEMA_VERSION` बंप पर, `.research-os/index.sqlite` को हटा दें और `research-os index build --all` को फिर से चलाएं। पैक अप्रभावित रहता है — इंडेक्सर साक्ष्य + दावों (कानून 8) के ऊपर एक त्वरण परत है; पुनर्निर्माण निष्क्रिय है।

**v0.12.1 पर कोई `trusted_baseline` समीक्षक प्रोफ़ाइल स्वीकार नहीं की जाती है।** यह एक जानबूझकर विश्वास मुद्रा है, अंतर नहीं: रिपॉजिटरी में अंशांकन रसीदें (`hermes-two-pass=failed`, `mistral-nemo-two-pass=conditional_pass`, `hermes-single-pass=comparison_only`, `hermes-two-pass-deterministic=failed`) साक्ष्य रिकॉर्ड करती हैं। विश्वास बार-बार बीज-विफलता स्मरण के माध्यम से अर्जित किया जाता है, न कि माना जाता है। ये रसीदें v0.8.0 MCP आर्किटेक्चर से पहले की हैं और उन्हें MCP पथ के तहत पुन: आधारभूत नहीं किया गया है।

## v1.0 का रोडमैप

v1.0 एक अर्जित स्थिति है, रिलीज़ तिथि नहीं। छह डॉगफूड प्रयोग (Exp1–Exp6, 2026-05-08 से 2026-05-11) बंद हो गए, प्रत्येक ने [`mcp-tool-shop-org/research-packs`](https://github.com/mcp-tool-shop-org/research-packs) में स्वीकार किए गए जमे हुए अनुसंधान-पैक का उत्पादन किया। आर्क ने v0.2.0 `research-os pack publish` + पैटर्न 2 (प्रयोग 2), v0.3.0 `--detector` ध्वज (F-09), v0.3.1 खंड-दायरे में छूट (F-10/F-11), v0.3.2 सामान्यीकृत स्वीकृत-दावा लेखांकन (F-36), v0.3.3 गेट-सिमेंटिक्स स्पष्टता (F-43/F-41), v0.4.0 स्रोत-सत्य अनुशासन (F-27/F-47/F-46), v0.5.0 समीक्षक अंशांकन एक स्थायी विश्वास अनुबंध के रूप में (F-48/F-49/F-50), और v0.6.0 नियतात्मक समीक्षक आधारभूत (F-53/F-54) अर्जित किया। v1.0 रिलीज़ की तैयारी एक बहु-चरणीय स्वास्थ्य/पॉलिश स्वार्म के माध्यम से चल रही है; आर्किटेक्चर लॉक पूरे समय बना रहता है। पूरी योजना [`docs/roadmap.md`](docs/roadmap.md) में।
