# v0.10.0 — Operator-Aloneness Repair Release

**Release date:** 2026-05-15
**npm:** `@mcptoolshop/research-os@0.10.0`
**Requires:** `ollama-intern-mcp@^2.4.0`

v0.10.0 closes the v0.1 operator-aloneness gate failure conditions surfaced on 2026-05-15 (`operator_aloneness_dst_v0.1`, FAIL). The release is a 4-slice repair arc: recovery routing alignment (R-002), scope-repair CLI (R-001), paired source-card audit hardening (R-003 + R-005), and honest `gather_outcome` status (R-004). The v0.1 gate FAILED because an external operator hit three independent walls — `recover` recommended the wrong unblock path, no CLI existed to repair `scope=null` claims, and source-card audit passed a fabricated COVID-19 card extracted from a 1035-byte APA Incapsula bot-check fragment. v0.10.0 closes those walls so v0.2 of the gate can fire against fresh operator runs.

## What shipped

### Slice 1 — recover advisor routes from gate state (R-002)

The diagnose layer in `src/recover/diagnose.ts` now reads `gate.json:blocking_reasons[]` and the cowork handoff section's `blocking_reasons[]` as the authoritative routing surface BEFORE falling back to the legacy `failures[].check` lookup. The gate-blocking signal wins over downstream signals like `source_card_classification_gap` and `high_frame_excluded_rate`.

The v0.1 gate failed in part because the recover advisor recommended `apply_source_card_override` when the gate was actually blocked on `accepted_claim_floor`. The legacy diagnose code looked for the synthetic check name `min_accepted_claims` but the gate emits `min_accepted_claims_and_sources` (per `src/gates/checks/accepted-claim-floor.ts`). The mismatch let the downstream classification-gap signal win. R-002 closes that decoupling.

The closed `FailureShape` enum is unchanged. New blocking-reason families require both a code mapping in `failureShapeFromBlockingReason()` and a fresh test in `test/recover-blocking-reasons-routing.test.ts`. The map is narrow on purpose.

### Slice 2 — claim repair-scope CLI + advisor action (R-001)

`research-os claim repair-scope <section> [--auto | --interactive]` lands as a new CLI. Default is interactive (least surprising for a new operator); a readline-backed prompter supports accept / edit / skip / quit on each proposal. `--auto` applies a templated heuristic — `"per <publisher> <source_type>, on <section_purpose>"` — without prompting. Graceful degradation when publisher or source_type is unknown.

An append-only ledger at `evidence/claim-scope-repairs.jsonl` records every repair, accept, edit, skip. The canonical claim row in `claims.jsonl` carries the latest `applied_scope`. Running repair-scope twice on the same claim preserves both records (Law 15 append-only audit-trail pattern, sibling to the v0.4 source-card-override ledger).

`RECOVERY_ACTIONS` grows from 7 to 8 closed values (`repair_claim_scope` joins). The action graph for `accepted_claim_floor` surfaces it as rank-1 when `evidence_state.needs_repair_claims >= 3`; below that threshold the legacy `add_on_topic_sources` ranking is preserved (repair alone cannot clear the floor). `apply_waiver` remains permanently forbidden on `accepted_claim_floor`; pack law is unchanged.

The v0.1 gate failed in part because 51 of 52 LLM-extracted claims arrived with `scope=null` and the operator had to hand-edit `claims.jsonl`. The 5-hand-edit step is architect knowledge; an external operator wouldn't know to do it. R-001 plugs the missing repair surface.

### Slice 3 — source-card audit hardening, paired (R-003 + R-005)

Two new severities ship together because they protect the same defense layer (audit, upstream of claim extraction) and were triggered together by the v0.1 APA Incapsula case.

**R-003 — `bot_check_or_captcha_detected` (HARD FAIL).** Compound signals: markers (`captcha`, `incapsula`, `cloudflare challenge`, `please verify you are human`, `robot check`, `_Incapsula_Resource`, `access denied`) paired with body-shape evidence (≤100 prose words by default). Independent compound signals: <2KB body with >50% `<script>` density; substantial scripts with ≤50 prose words after stripping; HTTP 200 + response time ≤100ms + body <2KB. Marker-substring alone does NOT fire — false-positive guard for legitimate CAPTCHA-research prose, verified on long-form research bodies.

**R-005 — `extraction_suspect_word_count_mismatch` (WARN AND QUARANTINE).** Fires when fetched body word count ≤200 AND extracted card text ≥800 words AND ratio ≥4. Catches confabulated rich cards extracted from thin fetches that don't trip R-003's bot-check signatures (paywall previews, custom 403/410 responses).

**Quarantine semantics.** Both severities exclude their source from claim extraction by default. Source cards are written normally; the severity is computed at audit time and at claim-extract time from the same pure-function (`detectSeverities`). Both surfaces (audit + extract) see the same effective state.

**Operator override via `clear_severities[]`.** Extends the existing v0.4 source-card override-ledger schema. The refine relaxes to: at least one of `new_source_type`, `new_publisher`, OR `clear_severities` must be present. Cleared severities are removed from the effective findings — claim extraction proceeds; audit kind drops back to existing precedence (e.g., `override_applied`). The override ledger remains append-only; clearing is a recorded operator decision.

**Per-pack thresholds via `research.yaml`.** Optional `audit.severity_thresholds.{bot_check,extraction_word_count_ratio}` block. Each field is optional; absent fields fall back to `DEFAULT_SEVERITY_THRESHOLDS`.

The v0.1 gate failed in part because an APA URL returned 1035 bytes of Incapsula JS challenge content; the LLM extractor confabulated a fully-formed source card describing a fabricated COVID-19 mental-health study in Bangladesh from that fragment. `source-card audit` passed it. Downstream defenses caught the off-topic case (audit-density 142.9 claims/1k source words; frame critic off-topic exclusion). An on-topic hallucination from a similar fragment would have slipped through. Slice 3 closes the defense-in-depth gap at the audit layer.

### Slice 4 — honest gather_outcome status enum (R-004)

A 5-value `gather_outcome` enum on `FetchReceipt` (optional for back-compat with pre-v0.10 receipts; `gather()` always populates it on new fetches):

- `ok` — fetched + text extracted successfully
- `fetch_failed` — HTTP error, timeout, network failure, SSRF refusal
- `extraction_skipped` — fetched, extraction layer not applicable (PDF, binary)
- `extraction_failed` — fetched, extractor errored mid-extraction
- `bot_check_detected` — fetched, R-003 marker+body-words signal fired at gather

Precedence (highest to lowest): `fetch_failed > bot_check_detected > extraction_failed > extraction_skipped > ok`.

**Operator-facing progress messages rewritten** — no more bare "Failed" word in front of "ok HTTP 200":

- `· extraction_skipped (content_type=application/pdf; extractor not applicable) — receipt recorded for <url>` (bullet prefix; not a failure, just an unhandled content type)
- `! fetch_failed (http_error HTTP 404) — receipt recorded for <url>`
- `! extraction_failed (<error>) — receipt recorded for <url>`
- `! bot_check_detected (marker:incapsula, body_words=5) — receipt recorded for <url>`
- `ok` → silent (the existing `Gathering N/M <url>` line already announced)

**Bot-check integration — HYBRID.** Gather-layer runs a light marker+body-words check (R-003 Signal A only, default thresholds) using the canonical `BOT_CHECK_MARKERS` const exported from `src/sources/severities.ts`. Audit-layer R-003 in `source-card-audit.ts` stays unchanged and authoritative for the multi-signal quarantine path (per-pack thresholds, script-density, fast-response, full `reasons[]` in audit findings). Drift risk is bounded by precedence + the existing `clear_severities[]` override.

**Catch-block synthetic-receipt path** — `buildSyntheticFailureReceipt()` now stamps `gather_outcome: 'fetch_failed'` so the persisted receipt for catch-block-derived failures carries the rollup status even though the gather-loop derivation never runs for that URL.

The v0.1 operator was confused by `"Failed (ok HTTP 200)"` — the phrasing conflated outcomes. The operator had to inspect to understand the PDF case was "fetched but text extraction skipped." R-004 is operator-clarity (HIGH but not blocking for v0.2 gate readiness); shipping it closes the 4-slice arc cleanly.

## What this does NOT prove

- **v1 readiness.** v0.10.0 closes operator-aloneness gate v0.1 failure conditions; it does not certify v0.2 will pass.
- **v0.2 operator-aloneness gate verdict.** v0.2 runs against this npm version in a separate session. v0.10.0 is the prerequisite, not the proof.
- **Admissibility doctrine work.** Admissibility Slice 1 (the post-v0.2 doctrine arc) is NOT authorized until v0.2 PASS.
- **A win against cloud deep-research tools.** The product proof at `local-first-vs-cloud-research/` from v0.7.x identified cloud's advantages on readability and operator burden; v0.10.0 does not claim those have been overcome.
- **A complete trusted reviewer calibration.** Reviewer recalibration under the MCP path remains open. Existing v0.6.0 calibration receipts predate the v0.8.0 MCP architecture and have not been re-baselined.

## Preserved invariants

- `pack freeze` continues to refuse `repair_required` packs. Severity quarantine and `gather_outcome` enrichment do not make an incomplete pack freezable.
- `pack publish` continues to refuse packs without a valid freeze receipt.
- **Frozen-pack regression byte-identical** against v0.3.3 baselines for all four frozen packs — seventh consecutive release where this holds (v0.4 → v0.5 → v0.6 → v0.7 → v0.8 → v0.9 → v0.10).
- `accepted_claim_floor` remains unwaiveable. The recovery advisor still refuses to recommend `apply_waiver` for unwaiveable failures; the new `repair_claim_scope` action surfaces alongside the existing `add_on_topic_sources` action, neither of which is a waiver.
- Closed `FailureShape` enum unchanged (still nine values). R-002 routes through new blocking-reason → failure-shape mappings; the enum itself is preserved.
- MCP architecture unchanged. `ollama-intern-mcp@^2.4.0` carries through. `OLLAMA_INTERN_MCP_BIN` env / PATH discovery + `StdioClientTransport` wiring unchanged.

## Doctrine earned during the arc

- **Operator-aloneness gates surface load-bearing product gaps the engineering view cannot see.** v0.1 found six findings that would have been silent product defects without the gate. The cost of running the gate (one operator day) is small compared to the cost of building Admissibility Slice 1 on broken substrate.
- **Honest under-claiming is a real failure mode.** The v0.1 synthesis didn't lie about anything; it just didn't cover enough. Silent-confident-undercovering is distinct from silent-confident-wrong but equally disqualifying for a synthesis that purports to answer the question asked.
- **Repair-path collapse beats source-defense gaps as the fatal operator burden.** The v0.1 case showed downstream defenses caught the hallucination; the unrecoverable state was the gate-vs-advisor mismatch. The locked execution order (R-002 → R-001 → R-003+R-005 → R-004) reflects that: fix the recovery spine first, then the missing repair command, then harden ingestion.
- **Closed-enum discipline pays compounding dividends.** Three repairs in this arc grew closed enums (`RECOVERY_ACTIONS` 7→8, `SourceSeverity` +2, `gather_outcome` +5 from informal-status to enum). Each growth required schema + test + downstream consumer updates; each was caught at typecheck time, not runtime.
- **Hybrid detection paths must declare authority.** R-004's HYBRID bot-check choice (gather-layer informational, audit-layer authoritative) names the load-bearing surface explicitly. Drift risk is bounded by precedence + the override-ledger `clear_severities[]` field; informational duplication of a check is acceptable when authority is unambiguous.

## Compatibility

- `package.json` engines: `node >= 20`.
- Requires `ollama-intern-mcp@^2.4.0` (unchanged from v0.8.0). The MCP server is discovered via the `OLLAMA_INTERN_MCP_BIN` env var or PATH lookup.
- Default model `hermes3:8b` (override via `OLLAMA_INTERN_MODEL` or per-call `--model <name>`).
- Schemas evolve additively: pre-v0.10 `FetchReceipt` artifacts without `gather_outcome` or `fetch_duration_ms` continue to parse cleanly. Pre-v0.10 source-card-overrides ledger entries without `clear_severities[]` continue to parse cleanly. The four frozen packs were frozen pre-v0.10 — their receipts cannot regress on schema extensions that affect only new fetches and new audit runs.
