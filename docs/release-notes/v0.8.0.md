# v0.8.0 — Architecture recovery + frame-bound topicality

**Release date:** 2026-05-12
**npm:** `@mcptoolshop/research-os@0.8.0`
**Substrate:** `ollama-intern-mcp@^2.4.0`

---

v0.8.0 reconnects research-os to its declared local-LLM substrate (ollama-intern-mcp), enforces section topicality with an extraction-time critic, and produces section-scoped evidence-citation briefs from the resulting accepted claims. Pack-level narrative synthesis remains gated on whole-pack synthesis-readiness; this release does not ship narrative drafting.

This is a meaningful release. v0.7.1 was absorbed into v0.8.0 — the section-level synthesis machinery shipped here, but is correctly framed as evidence-citation output rather than narrative drafting. The architecture-recovery framing is honest: the README declared ollama-intern-mcp as a runtime requirement since the v0.1 scaffold (2026-05-06), but the code had internal direct-Ollama stubs bypassing the MCP. v0.8.0 closes that drift.

## What landed

- **MCP client substrate.** Binary discovery (`OLLAMA_INTERN_MCP_BIN` env or PATH) + `StdioClientTransport` wiring connect research-os to `ollama-intern-mcp@^2.4.0` over MCP. Replaces internal direct-Ollama stubs that previously bypassed the declared substrate.
- **Per-claim section-evidence critic** via `ollama_extract`. Every draft claim from every ledger window is judged against the section purpose at extraction time. The critic has final say on admission; the envelope's `frame_alignment` becomes calibration telemetry only.
- **`frame_excluded` review decision** in the `ReviewDecision` union. Claims judged off-topic are preserved with `frame_excluded: true`, kept out of synthesis evidence, but visible to operators in the cowork handoff and the review surfaces.
- **`frame_exclusion_reason` enum** with four values: `off_topic`, `background_only`, `source_chrome`, `critic_unavailable`. The model emits the first three; `critic_unavailable` is the system-state label for soft-fail.
- **`frame_exclusion_rationale`** — structured natural-language explanation stamped on every excluded claim so operators can audit what the critic withheld without re-running the critic.
- **`DEFAULT_WINDOW_CHARS` default 5000 → 3000** — sized for `hermes3:8b` at workhorse-tier 8K context. The smaller window is the regression-safe default.
- **Section-level evidence-citation brief.** `research-os synth section <id>` (and the alias-spelling `research-os synth workspace --section <id>`) produces a section-scoped evidence-citation index: `claim_id → assertion → evidence_excerpt → source_id`. NOT narrative prose. Output lives at `sections/<id>/synthesis/section-brief.md` + `section-synthesis.json`.
- **Cowork handoff surfaces `frame_excluded` as its own bucket**, separate from accepted / repair / rejected.

## Schema additions

`ClaimSchema` gains three optional fields, all back-compat for v0.7.x packs:

- `frame_excluded?: boolean` — defaults to `false`. Heuristic-extractor claims always carry `false`; MCP-extractor claims carry the critic's decision.
- `frame_exclusion_reason?: 'off_topic' | 'background_only' | 'source_chrome' | 'critic_unavailable'` — present only when `frame_excluded: true`.
- `frame_exclusion_rationale?: string` — present only when `frame_excluded: true`.

`ReviewDecision` union gains `'frame_excluded'`. Existing v0.7.x review records continue to validate unchanged.

## Locked semantics

- **Critic has final say.** The per-claim section-evidence critic is the admission gate. Extraction's envelope-level `frame_alignment` is telemetry only — it is no longer load-bearing.
- **Soft-fail inverts to exclude.** When the critic call fails (transport, parse, invalid label, empty rationale, timeout), the draft is recorded as `frame_excluded: true` with reason `critic_unavailable`. The prior soft-fail-admit behavior was admitting chrome content as on-topic high-confidence claims when the critic crashed mid-page. The safe default when topicality cannot be determined is exclusion.
- **`frame_excluded` does not block section promotion.** Promotion gates count admitted claims only; excluded claims are preserved on disk for audit and absent from the synthesis evidence base.
- **Gate / review / cowork wire-up.** Every surface that displays per-claim disposition now treats `frame_excluded` as its own bucket. Review reports, cowork handoffs, and gate audits no longer conflate exclusion with reviewer rejection.

## Operational substrate

- **`ollama-intern-mcp@^2.4.0` is required.** Earlier MCP versions lack the per-tier `num_ctx` settings that v0.8.0 relies on.
- **Binary discovery.** research-os looks for the MCP server binary via the `OLLAMA_INTERN_MCP_BIN` env var first, then PATH. The MCP client uses `StdioClientTransport`; no network port is opened by research-os.
- **`num_ctx` resolved CPU-spill timeout.** v2.4.0's per-tier num_ctx (`instant=4096`, `workhorse=8192` on dev-rtx5080) addressed the CPU-spill timeout that surfaced during Phase 1 diagnostic. Operators on smaller VRAM tiers should set tier overrides via the MCP server config — research-os does not introspect VRAM.

After extraction-time topicality enforcement and review, 20 accepted_for_synthesis claims from 4 distinct sources reach synth output. ## What's NOT in this release

- **Pack-level narrative prose synthesis.** Section-level synth is evidence-citation; pack-level narrative drafting is a future release decision.
- **Calibration receipt re-baselining for the MCP path.** Existing receipts (`hermes-two-pass=failed`, `mistral-nemo-two-pass=conditional_pass`, `hermes-single-pass=comparison_only`, `hermes-two-pass-deterministic=failed`) were produced under the pre-MCP path. No `trusted_baseline` reviewer profile is admitted at v0.8.0; calibration receipts under the MCP path are deferred.
- **Window-paging-aware extraction.** When a single claim's evidence spans two ledger windows, the current extractor cannot stitch them. Deferred to v0.9.x backlog.
- **33→20 synth-layer claim filter investigation.** Observed on the fresh pack; backlog item for v0.8.x.
- **Cosmology cache investigation.** Backlog item for v0.8.x.
