# v0.7.0 — Dogfood Swarm Hardening

**Release date:** 2026-05-11
**npm:** `@mcptoolshop/research-os@0.7.0`
**Tests:** 901/901 (713 → 901, +188 across the swarm)
**Frozen-pack regression:** all 4 packs byte-identical against v0.3.3 baselines

---

v0.7.0 hardens `research-os` after a full dogfood swarm: safer fetches, stronger pack publishing, resilient malformed-input handling, structured recovery errors, progress feedback, clearer operator docs, and preserved frozen-pack verification.

**This is a hardening release. v1.0 is not yet authorized.** A separate v1 readiness arc opens around fresh-pack production proof and operator-first product positioning. See the [v1.0 readiness reassessment](#v10-readiness-reassessment) section below.

## What landed

Four-stage swarm executed against the v0.6.0 tree on 2026-05-11. Each stage was a read-only audit → advisor triage → amend wave → read-only re-audit. Two cross-agent integration escapes were caught structurally and corrected forward.

### Stage A — bug/security (Wave 1 + Wave 2)

12 HIGH + 14 MED + 5 LOW closed across the audit pass. **47 new regression tests added.** Two notable items:

- **`gather` partial-write hazard.** Per-URL try/catch + per-exception `sourceIdAppender.flush()` preserves in-flight source IDs when a mid-loop fetch throws. Happy-path batched-flush optimization preserved.
- **A-RE-001 cross-agent escape caught + corrected forward.** Wave 1 landed a helper API without migrating the production caller (`gather.ts`). Phase 4b audit caught via end-to-end-through-actual-caller verification. Wave 2 deleted the deprecated path, migrated the caller, and added an `expect(...).toBe(undefined)` assertion on the public surface (old-API-dead doctrine).

### Stage B — proactive resilience + supply-chain (Wave 3)

8 hardening fixes + 3 release-doc fixes. **41 new regression tests added.** Notable:

- **Indexer malformed-record resilience.** Per-record / per-file / per-section try/catch with `malformed_jsonl_warnings` on `IndexBuildSummary`. One bad section no longer blocks healthy sections.
- **CI action SHA-pinning** + `permissions: contents: read` default-deny on all workflows. Dependabot ecosystem coverage extended to `/site` and `github-actions`.
- **B-E-004 npm provenance scope-downed to v1.x with disclosure** (GHA-OIDC vs. local TranslateGemma translation discipline conflict).

### Stage C — operator humanization (Wave 4 + Phase 4 correct-forward)

22 fixes + 1 Phase 4 correct-forward. **90 new regression tests added.** Notable:

- **`pack publish --force` canonical destructive-replace sentence** anchored verbatim across 8 surfaces with a regression test asserting the load-bearing substring on each. The misleading "preserves operator-authored files" framing was caught and removed.
- **`IndexNotBuiltError` command-text typo fixed** (`research-os index --all` → `research-os index build --all`). New command-text registry test scans all error-message strings naming `research-os <cmd>` and asserts each resolves to a registered Commander subcommand.
- **`research-os help <topic>` static subcommand** with 4 locked topics (`recovery`, `pack-publish`, `review`, `gather`). Cardinality unit-tested.
- **Per-error handbook pointer retrofit** on 12 ResearchOSError subclasses.
- **Long-running command progress feedback.** `--no-progress` / `--progress` flags with TTY auto-detect default across `review` / `gather` / `contradict map` / `pack publish`.
- **C2-RE-001 cross-agent escape caught + corrected forward.** Wave 4 landed env-var plumbing in `src/util/progress.ts` but framed Commander flag registration in `src/cli.ts` as a "C1 handoff" that was never picked up. Phase 4 read-only audit caught the gap via `node ./dist/cli.js gather --no-progress test` returning `unknown option`. Coordinator-inline correct-forward (commit `68130c6`) landed the 4 Commander registrations + `applyProgressFlags(argv)` helper + 13-case regression test asserting both env-var translation and the reproduction-flip from "unknown option" to "option accepted" at the binary layer.

### Stage D — presentation polish (Wave 6)

9 release-doc fixes + 2 polish/behavior boundary cases (PB-001 README section rename, PB-003 sidebar reorder) landed inline. PB-002 (label-casing v2.0-track lock) deferred. **2 new regression tests added** (whitespace defects in audit + claim-audit-density summary blocks). Zero behavior changes admitted. New handbook pages `recovery.md` (6-scenario partial-failure runbook) and `known-limitations.md` (3 disclosures). `:::caution` Starlight asides on destructive-action sites.

## Doctrine ratchets

Four discipline rules codified by the swarm, carried forward into all future amend work:

1. **End-to-end through actual caller.** Closure tests run through the live entrypoint, not helper-level. Old-API-dead grep proof required when an API is replaced. Earned from A-RE-001.
2. **Cross-domain handoff is a tracked work item, not a closeout footnote.** Pickups across agent boundaries get explicit IDs and owning agents. Earned from C2-RE-001.
3. **No working-tree archaeology.** No broad `git restore` / `stash` / `checkout` / `clean` / `reset` operations. Earned from a Stage A Wave 1 incident.
4. **Hard-gate items must be fillable BEFORE the shipcheck re-pass that authorizes tag/publish.** Initial shipcheck → fill gaps → re-pass shipcheck → tag is the canonical shape. Earned from a release sequencing error caught pre-action by the executor.

## Locks established at v0.7.0 (v1.x stability boundaries)

Operator-observable surfaces locked by v0.7.0 for v1.x semver discipline. New codes / topics / flags admissible in v1.x only as additive non-breaking; changes to these surfaces are v2.0-track:

- **Error code taxonomy** — 17 ResearchOSError subclasses. 13 candidate sibling codes deferred to v1.x backlog with intended use-cases documented.
- **Help-topic cardinality** — exactly 4 topics: `recovery`, `pack-publish`, `review`, `gather`. Cardinality unit-tested.
- **CLI summary label format** — `source-card audit` Capital-Case labels + gate/audit/freeze blocking-reason headers locked for v1.x (operator-script grep contract).
- **`pack publish --force` replace semantics** — replace (not merge) semantics locked. Canonical sentence anchored across 8 surfaces.

## Known caveats

Three honest disclosures preserved in [CHANGELOG.md](../../CHANGELOG.md) `Known limitations` and [`handbook/known-limitations.md`](https://mcp-tool-shop-org.github.io/research-os/handbook/known-limitations/):

- **B-E-001 frozen-pack version-stamp historical artifact.** All 4 frozen packs carry `research_os_version: '0.1.0'` in `pack.manifest.json` + `pack/research.yaml` despite being published under v0.3.3 / v0.4.0 / v0.5.0 / v0.6.0. Root cause: a pre-v0.4 hardcode in `src/intake/scaffold.ts` was never updated alongside releases. Fixed in Wave 3; existing packs remain frozen and verify-pack byte-identically against their original receipts.
- **B-E-004 npm provenance deferred.** v0.7.0 npm packages do not carry provenance attestation. Real provenance requires migrating publish to a GitHub Actions OIDC flow, which collides with the local TranslateGemma 12B translation discipline. Migration with the translation handoff worked out is planned post-v0.7.0.
- **B-A-003 indexer schema-migration disclosure.** Current contract: bumping `SCHEMA_VERSION` in `src/indexer/schema.ts` requires deleting `.research-os/index.sqlite` on next run. Read-side enforcement + additive `ALTER TABLE` migrations deferred. When `SCHEMA_VERSION` bumps, release notes for that version must include a `BREAKING: delete .research-os/index.sqlite` instruction.

## v1.0 readiness reassessment

The swarm hardened the machinery but did not produce the kind of evidence v1 requires. A failed v1.0.0 ship attempt on 2026-05-11 (rolled back within the npm 72h unpublish window) made this gap explicit: confusing "the contract is honest, the caveats are disclosed" with "the product is v1-shippable" elides the missing product-level proof. The next v1 readiness arc opens around five concrete blockers:

- **V1-BLOCKER-1 — Fresh current-version pack proof.** A new pack on a fresh topic, authored end-to-end on v0.7+ toolchain (not a historical frozen artifact that still passes byte-identical regression), frozen and published, audit-able without reading project history.
- **V1-BLOCKER-2 — Clean happy-path operator guide.** Top-to-bottom walkthrough that does not require the reader to be familiar with experiment history or swarm doctrine.
- **V1-BLOCKER-3 — Recovery guide proven against real failures.** `handbook/recovery.md` exercised against actual failure modes during V1-BLOCKER-1 pack production (induce 3-5 failure modes, document recovery).
- **V1-BLOCKER-4 — Reviewer trust story simplified.** Either earn a `trusted_baseline` for a default profile or commit explicitly to "comparison_only by default" with a clear opt-in path. Operator-facing answer should not require reading `docs/experiment-6-proof.md`.
- **V1-BLOCKER-5 — Release copy rewritten around product value, not caveat inventory.** Lead with what the product does and who it's for, not with the workflow's refusals.

See [`docs/v1-readiness-packet.md`](../v1-readiness-packet.md) reassessment section for the full history-honest record of the v1 readiness verdict revision.

## Use this release if

If you want to take `research-os` for a real run today — with safer ingestion, structured recovery paths, discoverable runbooks, and known limitations stated honestly — this is the release to use.

If you want a frictionless turnkey research product, v0.7.0 hardens the machinery; v1 will need to prove the product around it.
