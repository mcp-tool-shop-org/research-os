# v0.9.0 — Product Artifact Arc

**Release date:** 2026-05-14
**npm:** `@mcptoolshop/research-os@0.9.0`
**Requires:** `ollama-intern-mcp@^2.4.0`

v0.9.0 turns the v0.8 evidence spine into operator-useful artifacts. It adds section-level prose with paragraph-level provenance, partial-pack synthesis that consumes section prose rather than raw claims, and lawful recovery guidance embedded where blocked sections are disclosed. Freeze and publish semantics are unchanged: readable partial artifacts do not make an incomplete pack freezable or publishable.

## The arc

```
Slice 1 → sections readable                 (5 commits)
Slice 2 → incomplete packs readable          (3 commits)
Slice 3 → incomplete packs actionable        (2 commits)
```

## What shipped

### Slice 1 — section-level prose synthesis

`research-os synth section <section-id>` now produces readable Markdown prose at `sections/<id>/synthesis/section-synthesis.{md,json}` alongside the existing `section-brief.md` evidence index. Three-stage pipeline:

1. **Planner** — deterministic claim-to-role assignment over accepted claims. Stable section-chunking; tier-aware fan-out (planner chunk size 5 for reliability on hermes3:8b at workhorse-tier 8K context).
2. **Drafter** — LLM writes prose against pre-assigned clusters. Banned-opener guard refuses meta-preamble like "This synthesis provides…". Pack-prefix-stripped output.
3. **Verifier** — paragraph-level admission check. Faithful paragraphs land in `prose.paragraphs[]`; unfaithful paragraphs land in `proseError`.

Admission gate refuses sections where no accepted claim can carry an answer role (`proseError.code = 'no_answer_cluster'`). Accepted ≠ sufficient for synthesis.

### Slice 2 — partial-pack synthesis

`research-os synth pack --partial` produces a pack-level readable artifact (`synthesis/partial-pack-synthesis.{md,json}`) in `repair_required` packs. Honest disclosure: every excluded section is named with a structured reason from a closed enum (`gate_blocked` / `unrun` / `repair_required` / `prose_error` / `no_section_synthesis` / `brief_only`).

The drafter consumes Slice 1's section-synthesis artifacts (never raw claims, never source cards). Pack-level paragraphs cite section paragraph IDs (`<section_id>:<paragraph_id>`), preserving Law 4 (extraction may overproduce; synthesis may not inherit abundance).

**Slice 2c — deterministic cross-section answer bundle.** When ≥2 sections are included, a deterministic bundle planner preselects the required cross-section support before the drafter runs. The drafter writes against that preselected set; a validator + one-retry path enforces compliance. Persistent failure emits a structured `cross_section_answer_support_missing` proseError rather than silently admitting off-spec output.

### Slice 3 — lawful recovery advisor

`research-os recover pack` produces operator guidance for blocked, unrun, or failed sections at `recovery/blocked-section-recovery.{md,json}`. Four-layer architecture:

- **Layer 1 — Diagnosis.** Deterministic classifier maps section state to one of nine closed `FailureShape` values (`accepted_claim_floor` / `min_independent_publishers` / `primary_sources_required` / `high_frame_excluded_rate` / `prose_error_no_answer_cluster` / `prose_error_cross_section_missing` / `unrun` / `source_card_classification_gap` / `reviewer_needs_human_review`).
- **Layer 2 — Lawful action graph.** Pure function maps `FailureShape` → ranked allowed `RecoveryActionId` (7 closed values) + forbidden actions. Pack-law forbiddings are data-driven: `accepted_claim_floor → apply_waiver` and `prose_error_no_answer_cluster → rerun_stage` are permanently forbidden by code, never by LLM judgment.
- **Layer 3 — AI advisor.** Receives typed facts (counts, classifications), allowed/forbidden actions, and information-boundary disclosure. Writes prose: contrastive framing ("you might think X, but…"), `why_smallest_reversible`, `expected_outcome`, Hick's-Law-capped `also_consider` (≤2), `do_not[]`, `system_cannot_see[]`. Three completion paths: `ai_with_verifier_pass`, `ai_with_retry_pass`, `deterministic_fallback`.
- **Layer 4 — Verifier.** Seven closed rejection reasons, all deterministic. Retry path does NOT include the previous rejected output (Kim 2025 sycophancy-under-rebuttal mitigation).

### Slice 3b — recovery embedded in partial-pack synthesis

Recovery guidance is embedded under each excluded section in `partial-pack-synthesis.{md,json}` via a compact projection from the same in-memory recovery object that powers the standalone command. Single source of truth: `buildRecoveryArtifact()` + `writeRecoveryArtifact()` are extracted helpers shared by both callers; no duplicated decision logic. The embed carries:

- `recommended_action_id` (closed enum)
- `recommended_action` (1-sentence operator prose)
- `why_this_action` (1-sentence justification)
- `do_not[]` (forbidden actions with reasons)
- `advisor_path` (provenance)
- `source` (pointer to canonical artifact)

Discriminated-union schema includes a 4th explicit `recovery_unavailable` state (with closed `reason` + `detail`) for engine-failure cases. Silent omission is forbidden by the no-silent-skip guardrail: every excluded section in fresh output carries a populated `recovery_summary`.

## Architecture

Three scopes; one pattern.

```
deterministic structure  →  LLM prose  →  verifier admits before output
```

- **Slice 1 planner** — deterministic claim-role assignment; drafter writes prose from preassigned clusters; verifier checks paragraph faithfulness.
- **Slice 2c bundle planner** — deterministic cross-section support selection when ≥2 sections are included; drafter writes from preselected bundle; validator checks bundle compliance.
- **Slice 3 recovery advisor** — deterministic action graph computed per excluded section; AI writes contextual guidance within that lawful action space; verifier admits before output; deterministic fallback floor when AI fails.

The system enforces structure; the model writes prose within it; the verifier admits before output. The same pattern recurred across three otherwise-independent scopes during this arc.

## What this does NOT prove

- **v1 readiness.** v0.9.0 makes the artifact layer real. v1 readiness requires a different proof.
- **Fresh-pack operator-aloneness.** The arc's acceptance beds used pre-baked upstream stages (extract, review, gate) so the new artifact layers could be tested in isolation. The end-to-end operator workflow on a fresh evidence question has not been re-run with v0.9.0 yet.
- **A win against cloud deep-research tools.** The product proof at `local-first-vs-cloud-research/` from v0.7.x identified cloud's advantages on readability and operator burden; v0.9.0 does not claim those have been overcome.
- **A complete trusted reviewer calibration.** Reviewer recalibration under the MCP path remains open. Existing v0.6.0 calibration receipts predate the v0.8.0 MCP architecture and have not been re-baselined.

## Preserved invariants

- `pack freeze` continues to refuse `repair_required` packs.
- `pack publish` continues to refuse packs without a valid freeze receipt.
- **Frozen-pack regression byte-identical** against v0.3.3 baselines for all four frozen packs (sixth consecutive release where this holds).
- `accepted_claim_floor` remains unwaiveable. The recovery advisor refuses to recommend `apply_waiver` for unwaiveable failures; the deterministic action graph never lists it among allowed actions.
- Slice 1d admission gate. A section with accepted claims that none can carry an answer role still refuses synthesis as `no_answer_cluster`.

## Doctrine earned during the arc

- **Closure requires both refusal proof AND production proof — not one half.** Refusing to admit an incomplete pack is a partial product; producing readable partial output that honestly discloses what's missing is the other half.
- **Closure is the operator's call, not the executor's; "qualified yes" is not a yes.** Engine working ≠ product surface complete (Slice 3 → Slice 3b correction).
- **Deterministic structure + LLM prose + verifier is a load-bearing pattern across scopes.** Three slices, one pattern.
- **Real acceptance beds surface real brittleness; synthetic guesses miss it.** The multi-section bed surfaced PLANNER_CHUNK_SIZE timeouts and prompt-only cross-section enforcement failures that drove Slices 1f and 2c.
- **Schemas become load-bearing when consumed by downstream slices; backward-compatible evolution only.** Slice 1's section-synthesis.json is consumed by Slice 2; Slice 2c's partial-pack-synthesis.json is consumed by Slice 3b; Slice 3a's `SectionRecoveryResult` is projected by Slice 3b. Each downstream consumer requires the upstream to evolve additively.
- **Adversarial-positive fixtures earn their keep.** The Claude.ai source in Section 06 of the cloud-vs-local pack surfaced the admission gate gap (accepted ≠ sufficient).
- **Research-grounded design > first-principles improvisation.** New protocol earned 2026-05-13: `study-swarm` — when designing substantial product layers, dispatch parallel research agents and cite specific studies before locking the design.
- **No-silent-skip discipline.** When a system has multiple surfaces consuming the same upstream computation, surface-level failures must be EXPLICIT, not omissions. The discriminated-union `recovery_unavailable` shape is the schema-level expression.
- **Diagnose-layer best-effort tolerance for supplementary inputs while keeping load-bearing inputs strict.** Gate audit JSON is the load-bearing failure-shape signal; claims/reviews supply supplementary counts. Strict parsing of supplementary inputs creates fragility where it doesn't pay correctness dividends.
