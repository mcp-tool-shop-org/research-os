> *v1.0.0 is an honest contract release: the workflow is proven, the failure modes are disclosed, and synthesis remains gated by evidence. research-os does not ship a trusted reviewer model by default. It ships the machinery to prove, reject, or conditionally admit reviewer profiles.*

## What v1.0 ships

Eight concrete claims from the [v1.0 readiness packet](../v1-readiness-packet.md):

1. **Source truth before synthesis (Laws 1 and 4).** No synthesis is permitted until extracted claims have passed adversarial review and a section gate has returned `synthesis_eligible: true`. The gate is machine-enforced.
2. **Append-only ledgers throughout.** `claim-reviews.jsonl`, `source-card-overrides.jsonl`, `evidence/fetch-log.jsonl`, `calibration/reviewer-profiles/<profile>/runs/run-NNN.json` — all append-only. Effective state derived from the ledger, not asserted.
3. **Deterministic freeze receipts with byte-identical verification.** `freeze` produces `audits/freeze-receipt.json` that is independently reproducible via `research-packs/scripts/verify-pack.mjs`. All 4 archived packs byte-identical against v0.3.3 baselines through v1.0.0.
4. **Machine-enforced pack publication contract.** `pack publish` refuses packs missing freeze receipt or synthesis artifacts. Frozen-pack refusal for `--apply` operations is unconditional.
5. **Section gates with pack-wide and section-scoped source-floor accounting.** Seven gate families; section-scoped waivers available for structurally single-publisher domains with non-empty `reason` and `compensating_controls[]`.
6. **Reviewer calibration machinery with durable receipts.** Four status labels (`trusted_baseline`, `conditional_pass`, `failed`, `comparison_only`); eight PASS/FAIL bars; multi-run median aggregation with recurring-failure demotion.
7. **Explicit caveat handling with audit-trail preservation.** Section-scoped waivers and waived rows preserved annotated; calibration receipts disclose `unreachable_decisions[]`; review output discloses `reviewer_options` directly.
8. **Reproducible operator workflow from pack config.** `reviewer_options` in `research.yaml` carries sampling parameters; production `research-os review` extracts them from the preset and threads into both reviewer passes. Operators reproduce a calibrated baseline from config, not memorized CLI flags.

## What v1.0 does NOT ship

Six honest non-claims:

1. **It is not a report generator.** Synthesis prose remains operator-authored. `synth workspace` creates guardrail-headed workspace files; it does not write synthesis.
2. **It is not an autonomous truth machine.** It structures gathered evidence and gates synthesis eligibility. The operator makes all research judgments.
3. **It does not ship a trusted reviewer model by default.** No profile earns `trusted_baseline` at v1.0. Canonical receipts at v0.6.0: `hermes-two-pass` → `failed`; `hermes-two-pass-deterministic` → `failed`; `mistral-nemo-two-pass` → `conditional_pass`; `hermes-single-pass` → `comparison_only`. **`trusted_baseline` is earned through the harness — not claimed by the developer.**
4. **It does not guarantee web accessibility for JS-shell or paywalled sources.** F-42 (Apple `developer.apple.com`) and F-44 (Valve/Steam JS-shell entire web surface) are documented structural ceilings. Operator workarounds exist.
5. **It does not make weak sources strong through waivers.** Waivers require non-empty `compensating_controls[]` and `reason`. Pack policy `primary_source_waiver_allowed: false` blocks all waivers.
6. **It does not make synthesis decisions for the operator.** `forbidden_inputs[]` enumerates non-accepted claims; what to write with accepted claims is the operator's work.

**Doctrine ratchets codified by v1.0:**

1. **End-to-end through actual caller** — closure tests run through the live entrypoint, not helper-level. Earned from A-RE-001.
2. **Cross-domain handoff is a tracked work item, not a closeout footnote** — pickups across agent boundaries get explicit IDs and owning agents. Earned from C2-RE-001.
3. **No working-tree archaeology** — when state is surprising, STOP and report; no broad `git restore` / `git stash` cleanup. Earned from a Stage A Wave 1 incident.
4. **Hard-gate items must be fillable BEFORE the shipcheck re-pass that authorizes tag/publish** — initial shipcheck → fill gaps → re-pass shipcheck → tag is the canonical shape. Skipping the re-pass is a release-procedure violation. Earned from an advisor sequence error caught by the Phase 10 executor pre-action.

## Known limitations — historical disclosure for v1.0

Three honest disclosures preserved in [CHANGELOG.md](../../CHANGELOG.md) `Known limitations` and [`handbook/known-limitations.md`](https://mcp-tool-shop-org.github.io/research-os/handbook/known-limitations/):

1. **Frozen-pack `research_os_version: '0.1.0'` historical artifact (B-E-001).** All 4 frozen packs carry `research_os_version: '0.1.0'` in `pack.manifest.json` + `pack/research.yaml` despite being published under v0.3.3 / v0.4.0 / v0.5.0 / v0.6.0. Root cause: a pre-v0.4 hardcode in `src/intake/scaffold.ts` was never updated alongside releases. Fix landed in Wave 3 (`c804f04`); existing packs remain frozen and verify-pack byte-identically against their original receipts. Future packs stamp the live version.
2. **npm provenance attestation deferred to v1.x (B-E-004).** v1.0 npm packages do not carry provenance attestation. Real provenance requires migrating publish out of local advisor sessions into a GitHub Actions OIDC flow, which collides with the local TranslateGemma 12B translation discipline. Migration to a CI-based publish flow with the translation handoff worked out is planned for v1.x.
3. **Indexer schema-version migration model (B-A-003).** v1.0 contract: bumping `SCHEMA_VERSION` in `src/indexer/schema.ts` requires deleting `.research-os/index.sqlite` on next run. Read-side enforcement + additive `ALTER TABLE` migrations are deferred to post-v1.0. Until enforcement lands, treat this as a release-note disclosure: when `SCHEMA_VERSION` bumps, the release notes for that version must include a `BREAKING: delete .research-os/index.sqlite` instruction.
